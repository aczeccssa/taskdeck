LATEST RELEASE · V0.2.0

Smaller audit footprint. Safer network defaults.

Version 0.2.0 limits audit growth and search payloads, avoids migration-lock contention on current databases, preserves more scheduled-run history, and requires explicit authorization before a native daemon listens beyond localhost.

Read the v0.2.0 release notes →
▤

Bounded audit history

Retention keeps the replication queue and recent local history within defined limits. Search indexes bounded excerpts while detail views keep the full stored record.

◷

Faster database opens

Current-schema startup skips the migration lock and full integrity scan. Run taskdeck node integrity-check when you want an explicit check.

✓

Clearer scheduled-run history

Already-running skips and still-running attempts closed by daemon shutdown or restart now receive terminal history records.

⌑

Safer remote access

Native installs listen on localhost by default. Remote binding requires an explicit opt-in, and Unix state files use owner-only permissions.

BUILT FOR THE WHOLE LOOP

From the first command to the last alert.

Taskdeck keeps execution, coordination and observability in the same model, so your tools share the same state.

▣

Tasks that stay alive

Persistent daemon state, retained metrics and process controls that survive a detached terminal or a restart.

◇

Workflows with structure

Arrange task cards, connect dependencies and run groups in topological order with failure handling.

▤

Boards for the big picture

Pin tasks across nodes and workspaces into an operational board for one glance status.

◉

Alerts that reach you

Subscribe to lifecycle events, keep an inbox and deliver JSON webhooks.

⌘

MCP for automation

Expose the same node-aware controls to MCP clients through the embedded Streamable HTTP server.

◎

Workers that scale out

Use a standard leader, pure master or local worker without separate builds.
